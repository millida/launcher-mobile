# Как помочь проекту

[English version: CONTRIBUTING.md](CONTRIBUTING.md)

Millida Launcher для Android — лаунчер Minecraft Java Edition на Kotlin и Jetpack
Compose. `core` устанавливает и запускает игру и ничего не знает про Android,
`runtime` держит Java-машину на телефоне, `app` — интерфейс поверх них.

Спасибо, что хотите помочь. Ниже — всё, что нужно, чтобы поднять проект,
сделать правку в стиле остального кода и оформить pull request так, чтобы его
можно было быстро посмотреть.

## Как устроен этот репозиторий

Разработка идёт во внутреннем репозитории. Каждый выпуск приходит сюда одним
коммитом «Millida Mobile X.Y.Z» со всем кодом этой версии, и этот коммит заменяет
прежнее дерево. Поэтому pull request здесь не вливается напрямую: если мы
принимаем правку, мы переносим её в репозиторий разработки, и сюда она приходит
со следующим выпуском.

## Что поставить

- JDK 17 или новее.
- Android SDK с **Android 15 (API 35)**, **NDK 27** и **CMake 3.22.1**.

Проще всего получить всё это через Android Studio. Пошагово — в
[BUILDING.ru.md](BUILDING.ru.md).

## Запуск

```bash
./gradlew :app:assembleDebug
adb install app/build/outputs/apk/debug/app-debug.apk
```

Отладочная сборка — отдельное приложение `net.millida.launcher.debug`: ставится
рядом с официальным лаунчером и его данные не трогает. Java-машины и рендереров в
отладочном APK нет — они скачиваются при первом запуске игры.

Логика, которой не нужен телефон (установка, профили, аккаунты, аргументы
запуска), живёт в `core` и работает на настольной Java, поэтому большинство правок
проверяется тестами, без устройства.

## Что прогнать перед pull request

```bash
./gradlew :core:test                 # логика ядра на настольной Java
./gradlew :app:testDebugUnitTest     # интерфейс и логика приложения (Robolectric)
./gradlew :bridge:jar                # замена GLFW, которая работает внутри игры
./gradlew :app:assembleDebug         # сам APK
```

Это те же команды, что гоняет наш CI на каждую правку. Если правка касается
запуска игры, рендера или ввода, проверьте её и на живом телефоне и напишите в
pull request, на каком: тесты не ловят чёрный экран.

## Стиль кода

Конфига форматтера нет, поэтому ориентир — соседний код:

- Kotlin, отступ 4 пробела, `camelCase` для функций и переменных, `PascalCase` для
  классов и composable-функций, `UPPER_SNAKE_CASE` для констант.
- Границы модулей соблюдаются: `core` не зависит от Android, `runtime` — от
  интерфейса, `app` не работает с файлами игры напрямую.
- Новую функцию кладите рядом с родственными, а не в общий модуль.
- Данные извне (сеть, архивы, имена файлов, манифесты) — недоверенные: пути и
  хеши проверяются до использования.

**Комментарии**

Код должен читаться сам: понятные имена, небольшие функции, явные типы вместо
пояснений. Комментарий оставляйте там, где он объясняет неочевидное «почему», а не
пересказывает «что»: обход бага драйвера или Android, требование протокола
Minecraft или внешнего API, причину неинтуитивного порядка шагов.

Новые комментарии пишите по-английски, чтобы код одинаково читали все, кто
заглядывает в репозиторий. Правило касается только комментариев в коде.

## Pull request

В описании напишите:

- **Что и зачем**: какую проблему решает правка. Если есть issue — ссылку на него.
- **Как проверяли**: какие команды запускали и что делали руками — на каком
  телефоне и версии Android, с какой версией Minecraft и загрузчиком, какой
  сценарий воспроизводили.
- **Скриншот или короткая запись** — обязательно для всего, что меняет интерфейс.

Отдельно скажите, если правка меняет формат пользовательских данных: настройки,
профили, аккаунты, раскладку файлов игры. Такое ломает уже установленные
лаунчеры, поэтому нужна миграция и понятная пометка в описании.

## Куда писать

- **Баг или идея** — [issue](https://github.com/millida/launcher-mobile/issues/new).
  К багу приложите отчёт из приложения: после вылета — кнопка «Отправить отчёт», в
  остальных случаях — вкладка «Логи» в сборке.
- **Уязвимость** — не в issue. Порядок описан в [SECURITY.ru.md](SECURITY.ru.md).

В общении придерживаемся [кодекса поведения](CODE_OF_CONDUCT.ru.md).
